## 📋 Что Делает Мастер

### 1️⃣ Настройка Supabase - API Ключи

**Мастер:**
- Спросит Reference ID вашего Supabase проекта
- Откроет страницу API настроек в браузере
- Попросит скопировать:
  - `NEXT_PUBLIC_SUPABASE_URL`
  - `NEXT_PUBLIC_SUPABASE_ANON_KEY`

**Вам нужно:**
1. Создать проект на [supabase.com](https://supabase.com)
2. Скопировать Reference ID из URL (например: `abcdefgh`)
3. Вставить ключи, когда мастер спросит

---

### 2️⃣ Настройка Supabase - База Данных

**Мастер:**
- Откроет страницу настроек базы данных
- Попросит Connection String (DATABASE_URL)
- Предложит выполнить SQL миграцию автоматически

**Вам нужно:**
1. Скопировать Connection String (URI format)
2. **ВАЖНО:** Заменить `[YOUR-PASSWORD]` на реальный пароль базы данных
3. Подтвердить выполнение миграции

**Что создаст миграция:**
- 8 таблиц (salons, staff, clients, services, appointments, inventory)
- Row Level Security (RLS) политики
- Триггеры и функции
- Индексы для производительности

---

### 3️⃣ Настройка GitHub - Репозиторий

**Мастер:**
- Откроет страницу создания нового репозитория
- Попросит URL репозитория
- **Автоматически** выполнит:
  - `git init`
  - `git add .`
  - `git commit -m "Initial commit: Beauty Pro CRM Setup"`
  - `git branch -M main`
  - `git remote add origin [URL]`
  - `git push -u origin main`

**Вам нужно:**
1. Создать репозиторий на GitHub
2. **НЕ добавлять** README, .gitignore или LICENSE
3. Скопировать HTTPS URL (например: `https://github.com/username/repo.git`)
4. Вставить URL, когда мастер спросит

**Обработка ошибок:**
- Если remote origin уже существует - обновит URL
- Если обычный push не работает - предложит force push
- Если коммит уже есть - пропустит создание

---

### 4️⃣ Настройка Vercel - Деплой

**Мастер:**
- Откроет страницу импорта проекта в Vercel
- Покажет инструкцию по деплою
- Выведет переменные окружения для копирования

**Вам нужно:**
1. Импортировать GitHub репозиторий в Vercel
2. Добавить Environment Variables:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
3. Нажать "Deploy"
4. После деплоя обновить `NEXT_PUBLIC_APP_URL` в `.env.local`

---

### 5️⃣ Финализация

- Установит `pg` для работы с PostgreSQL
- Проверит все зависимости
- Покажет итоговое сообщение с инструкциями

## 🎯 Пошаговая Инструкция

### Подготовка (5 минут)

1. **Создайте Supabase проект:**
   - Зайдите на [supabase.com](https://supabase.com)
   - Нажмите "New Project"
   - Введите название, пароль, регион
   - Дождитесь создания (~2 минуты)
   - Запомните или сохраните пароль базы данных!

2. **Подготовьте GitHub:**
   - Убедитесь, что вы залогинены
   - Подготовьте название для репозитория

3. **Подготовьте Vercel:**
   - Убедитесь, что вы залогинены
   - Подключите GitHub аккаунт к Vercel

### Запуск Мастера (5 минут)

```bash
# 1. Установите зависимости (если еще не установлены)
npm install

# 2. Запустите мастер
npm run setup
```

### Следуйте Инструкциям

Мастер будет задавать вопросы и открывать нужные страницы в браузере. Просто отвечайте и копируйте запрашиваемые значения.

**Общий процесс:**
1. Введите Supabase Project ID
2. Скопируйте API ключи
3. Скопируйте Database URL (замените пароль!)
4. Подтвердите миграцию базы данных
5. Создайте GitHub репозиторий и вставьте URL
6. Дождитесь автоматического push на GitHub
7. Перейдите в Vercel для деплоя
8. Готово!

## ⚠️ Решение Проблем

### "Git не установлен"
```bash
# macOS
brew install git

# Windows
# Скачайте с https://git-scm.com/download/win

# Linux (Ubuntu/Debian)
sudo apt-get install git
```

### "Требуется Node.js 18+"
```bash
# Проверьте версию
node -v

# Установите через nvm (рекомендуется)
nvm install 18
nvm use 18

# Или скачайте с https://nodejs.org/
```

### "Ошибка подключения к базе данных"
**Причины:**
1. Неправильный пароль в DATABASE_URL
2. База данных не готова (подождите 1-2 минуты)
3. Firewall блокирует соединение

**Решение:**
1. Проверьте пароль в Connection String
2. Убедитесь, что база запущена (зайдите в Supabase Dashboard)
3. Попробуйте выполнить миграцию вручную через SQL Editor

### "Git push не работает"
**Причины:**
1. Репозиторий уже содержит файлы
2. Нет прав доступа к репозиторию
3. Remote origin уже настроен на другой URL

**Решение:**
1. Создайте **пустой** репозиторий (без README)
2. Проверьте права доступа на GitHub
3. Мастер предложит force push - согласитесь

### "Миграция базы данных не выполнилась"
**Решение:**
1. Зайдите в Supabase Dashboard
2. Перейдите в SQL Editor
3. Откройте `supabase/migrations/001_initial_schema.sql`
4. Скопируйте весь SQL код
5. Вставьте в SQL Editor и выполните (Run)

## 💡 Советы

### Для Продакшна
1. Используйте **отдельный** Supabase проект для production
2. Создайте `.env.production` для production переменных
3. В Vercel добавьте переменные для Production environment
4. Включите email confirmation в Supabase Auth

### Для Команды
1. Каждый разработчик запускает `npm run setup` локально
2. Используйте **один** GitHub репозиторий
3. У каждого свой `.env.local` (не коммитить!)
4. Деплой делает только один человек

### Безопасность
- ⚠️ **Никогда не коммитьте .env.local!** (он в .gitignore)
- ⚠️ Используйте сильные пароли для базы данных
- ⚠️ Service Role Key храните только в Vercel, не в .env.local
